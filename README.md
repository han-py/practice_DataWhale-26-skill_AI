<summary>关于报错内容的启示</summary>
<br>
根据 `报错内容.md` 与 `Skill审核驳回问题分析&直播课建议参考.md` 的汇总，提交包常见被驳回的主要原因是对用户/外部动态内容未做充分净化，导致 Markdown 表格结构被破坏或在表格软件中触发公式、以及保留了境外平台/服务残留等问题。核心防护要点：在写入 Markdown 表格/标题/列表前压平换行并转义 `|`、转义或替换 `< > &` 与反引号，去活化 Markdown 链接/图片与危险协议（如 `javascript:`/`data:`）；对单元格内容应按首个非空白字符判断是否以 `=` `+` `-` `@` 开头，命中时在前面加单引号或等效前缀以防公式注入；对来源 URL 做展示文本与链接校验；提交前全仓搜索境外服务关键字（如 `openai`、`claude`、`google` 等）并清理非必要引用；运行示例命令与单元测试，确认在 Windows 控制台环境下（UTF-8）没有编码错误。简短自检清单：

- 所有动态字段统一走 `sanitize` 流程（换行->折叠、转义、首字符公式检查）
- 表格/CSV 导出前对公式前缀做基于首个非空白字符的处理
- 全仓关键词搜索并移除或说明外部平台引用
- 运行示例命令与单元测试，确认 Windows 控制台不崩溃

将以上作为提交前的最低校验项，可显著降低被驳回概率。
